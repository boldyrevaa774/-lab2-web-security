# Лабораторная работа №2 — основы веб-безопасности

## Цель работы

Создать локальное Python веб-приложение, продемонстрировать две учебные уязвимости из OWASP Top 10, проверить их Python-скриптом и показать исправления.

## Реализованные уязвимости

1. **SQL Injection (A03: Injection, OWASP Top 10 2021).** Данные формы входа напрямую объединяются со строкой SQL-запроса.
2. **Reflected XSS (A03: Injection, OWASP Top 10 2021).** Поисковый запрос вставляется в HTML без экранирования.

Обе уязвимости намеренно созданы только для локальной демонстрации. Не размещайте уязвимую версию в интернете и не используйте скрипт против чужих сайтов.

## Требования

- Python 3
- Браузер
- Дополнительные пакеты не требуются

## Часть 1. Запуск уязвимого приложения

Откройте терминал в папке проекта:

```bash
python vulnerable_app.py
```

Откройте в браузере:

http://127.0.0.1:8000

Тестовая учётная запись для обычного входа:

- Логин: `admin`
- Пароль: `admin123`

## Часть 2. Демонстрация уязвимостей

Не закрывая терминал с сервером, откройте второе окно терминала и выполните:

```bash
python exploit.py
```

Скрипт отправляет два запроса только на `127.0.0.1`:

- тестирует SQL Injection в форме входа;
- проверяет, возвращает ли поиск HTML/JavaScript-маркер без экранирования.

Для наглядной проверки XSS можно открыть в браузере:

http://127.0.0.1:8000/search?q=%3Cscript%3Edocument.body.dataset.xss%3D%27executed%27%3C%2Fscript%3E

## Часть 3. Исправление уязвимостей

Остановите уязвимый сервер сочетанием `Ctrl+C`.

Запустите исправленную версию:

```bash
python secure_app.py
```

В другом терминале снова выполните:

```bash
python exploit.py
```

Теперь тестовый вход с SQL-инъекцией не должен проходить, а HTML-маркер XSS должен отображаться как обычный текст, а не интерпретироваться как HTML.

## Что исправлено

### SQL Injection

Было:

```python
sql = (
    "SELECT username FROM users "
    f"WHERE username = '{username}' AND password = '{password}'"
)
result = connection.execute(sql).fetchone()
```

Стало:

```python
sql = "SELECT username FROM users WHERE username = ? AND password = ?"
result = connection.execute(sql, (username, password)).fetchone()
```

Параметры передаются отдельно от SQL-команды. Поэтому введённый текст рассматривается как значение, а не как часть SQL-кода.

### XSS

Было:

```python
content = f"<p>Вы искали: {query}</p>"
```

Стало:

```python
from html import escape

safe_query = escape(query)
content = f"<p>Вы искали: {safe_query}</p>"
```

Функция `escape()` заменяет специальные HTML-символы на безопасные представления.

## Вывод

В ходе лабораторной работы было разработано локальное веб-приложение на Python. В приложении были намеренно реализованы SQL Injection и reflected XSS. С помощью отдельного Python-скрипта были отправлены тестовые HTTP-запросы, подтверждающие наличие уязвимостей. Затем уязвимости были исправлены: для SQL использованы параметризованные запросы, а пользовательский ввод при формировании HTML экранируется. Повторная проверка показала, что тестовые воздействия больше не дают исходного результата.
